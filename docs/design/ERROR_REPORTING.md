# Error Reporting

## Назначение

Error Reporting хранит технические ошибки отдельно от telemetry-событий. Telemetry остаётся append-only диагностическим журналом, а error report — управляемой рабочей записью с владельцем процесса исправления.

## Lifecycle

```text
new → fixing → fixed → verified → closed
```

Переходы выполняются последовательно через `PATCH /api/errors/{id}`. Отчёт содержит correlation ID, компонент, тип ошибки, безопасный контекст, ссылку на исправление и результат проверки.

## API

- `GET /api/errors?status=all&limit=200` — список отчётов и счётчики по статусам;
- `POST /api/errors` — ручное создание отчёта;
- `GET /api/errors/{id}` — один отчёт;
- `PATCH /api/errors/{id}` — следующий lifecycle-статус и данные исправления.

HTTP-ответы 5xx и необработанные ошибки автоматически создают отчёт с correlation ID и маршрутом запроса. Контекст очищается от полей, похожих на секреты или содержимое сообщения.

Веб-интерфейс доступен по маршруту `/errors`.

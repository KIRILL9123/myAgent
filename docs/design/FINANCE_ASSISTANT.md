# Finance через Assistant и Telegram

Статус: active, реализовано 2026-08-04.

Finance не имеет отдельной логики для веб-чата и Telegram. Оба канала передают
сообщение в один orchestrator и используют один `TOOL_REGISTRY`; поэтому схема,
валидация, permission level, audit event и service handler не расходятся.

## Контракт инструментов

| Инструмент | Назначение | Permission |
| --- | --- | --- |
| `add_transaction` | Одна уже совершённая операция | GREEN |
| `get_transactions` | Чтение журнала с фильтрами | GREEN |
| `get_summary` | Итоги за период | GREEN |
| `get_finance_forecast` | Прогноз активных повторяющихся операций на 1–24 месяца | GREEN |
| `add_recurring_template` | Явно запрошенный пользователем повторяющийся шаблон | GREEN |

`add_transaction` используется для разовой операции. Для регулярной операции
ассистент сначала должен понять частоту и расписание, а затем вызвать
`add_recurring_template`: `weekly` требует `day_of_week` (понедельник — `0`),
`monthly` требует `day_of_month`, `yearly` — `month_of_year` и `day_of_month`.
Неполное расписание отклоняется Pydantic-моделью до вызова сервиса.

## Правила поведения

- Валюта передаётся как ISO-код, если она известна; разные валюты не складываются
  и не конвертируются без отдельного курса.
- Просмотр журнала, итогов и прогноза не требует подтверждения.
- Создание повторяющегося финансового правила допускается только при явном
  запросе пользователя; само по себе упоминание будущего платежа не создаёт
  шаблон.
- Telegram не дублирует Finance API: его tool call идёт через тот же registry и
  `finance_service`, что и веб-чат.
- Ближайшая операция из активного recurring template проецируется в Today и
  Notification Center и может попасть в общий Telegram digest. Шаблон,
  связанный с подпиской, показывается только через subscription signal.

Подробные правила хранения валют, повторений и идемпотентности находятся в
[FINANCE_MODEL.md](FINANCE_MODEL.md). Регрессия общего контракта закреплена в
`backend/tests/test_finance_tools.py`.
